术语表

课程使用的稳定词汇。定义强调“它拥有什么权力”以及“它不能替代什么”，便于源码评审与验收沟通。

架构与能力

ProjectProfile

项目治理档位：Lite、Standard 或 Governed。它是 Capability Compiler 的输入，不是一条独立硬编码流水线。

CapabilityPlan

将 Profile、Risk、Policy、Provider 与依赖闭包编译成的权威能力决议，包含活动模块、绑定和 Operation DAG。

Operation DAG

一次工作流实际执行的有向无环图。未启用模块不产生节点、绑定、Checkpoint 或空结果。

Kernel

所有 Profile 共享的确定性主干，例如 Capture、Plan、Context、Execute、Verify 与 Snapshot。

Module

由 CapabilityPlan 条件物化的治理能力，例如 Impact、Design、Evaluation、Strict TDD 与 Audit。

Port

模块公开的类型化能力边界。Port 存在只证明“允许连接”，不证明生产代码已连接 Provider 或消费者。

事实、图与存储

Node

Graph 中的类型化工程对象，例如 Requirement、Task、Evidence 或 Snapshot。

Edge

两个 Node 之间的类型化关系。合法端点不代表 Impact Engine 会自动传播。

Artifact Graph

长期工程知识视图，关注意图、需求、设计、组件、代码和测试怎样关联。

Execution Graph

运行治理视图，关注 Plan、Task、Context、Run、Gate、Evidence 与恢复记录。

Ledger

Git-native、append-only 的权威记录。Lifecycle Event、Node、Edge、Approval 与 Evidence 由它决定完成真相。

Projection

从 Ledger 可重建的读侧表示，例如 SQLite、Markdown 或 Dashboard View；投影不能反向升级为事实。

Live Spool

保存心跳、相位和输出摘要等 Observation Event 的可删除实时层，不参与完成裁决。

Digest

canonical 内容的稳定摘要。Approval、Context、Evidence 或 Binding 的输入漂移会改变 digest 并触发失效。

需求、执行与完成

Criterion

一条原子验收准则。每个 accepted Criterion 恰好编译出一个 canonical Assertion。

Test seed

由 Criterion 稳定派生的测试图节点，为后续 Assertion 与 Evidence 提供追踪锚点。

Assertion

Harness 确定性编译的可判定验收义务；模型可以分组，不能创造、合并或删除它。

TaskTddContract

Task 的不可变 TDD 合同，绑定 Assertion、Test、Design strategy、Plan 与 CapabilityPlan digest。

Evidence

带来源、类型、绑定和 freshness 的结果记录。Agent 自述、日志片段或旧 commit 测试不能自动成为当前 Evidence。

TaskVerdict

逐 Assertion 消费有效 Evidence 后的任务裁决。Provider Run 成功不等于 TaskVerdict 通过。

Snapshot

Iteration 完成后的权威锚点，记录 source commit、ledger commit、Gate、Evaluation、Verdict 与遗留风险。

Fail closed

输入、绑定或证据不完整时停止并返回 typed blocker，而不是猜测、降级或制造空壳成功。

模型治理与状态

Model Slot

Capability Binding 使用的五个固定槽位：Impact、Design Review、Plan、Feedback、Grounded Synthesis。

Purpose

Grounded Synthesis 的固定用途：Discovery、Context Enrichment、Approval Brief、Iteration Narrative。

Provider Binding

将 slot/purpose 与 Provider、Prompt、Schema、预算和失败模式绑定的可摘要记录；凭据材料不进入 digest。

Managed Runner

统一模型调用状态机，只接受编译 Prompt 与 Binding，记录 planned 到 consumed/failed 的全过程。

已连通

当前生产消费点存在，并有当前提交上的自动化或 Ledger 证据；仍需注明是仓库内还是外部环境。

部分连通

接口或生产路径存在，但外部 Provider、完整闭环或发布环境证据尚不完整。

未连通

只有目标设计、类型或孤立组件，当前生产调用链没有消费者。

Evidence scope

证据适用的 commit、平台、Provider、Profile、命令和时间范围。脱离 scope 的“通过”不能外推。
