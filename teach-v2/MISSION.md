# Mission：独立读懂 Universal Harness

## 学习成果

完成课程后，你应当能够脱离原实现助手：

- 画出系统主链，并说清 Kernel、Module、CapabilityPlan、Evidence 与 Ledger 的责任边界。
- 从一个技术设计声称出发，沿生产调用链定位核心源码，而不是只找到类型或接口定义。
- 解释源码的调用者、输入、输出、不变量、失败语义与证据边界。
- 区分“代码存在、仓库内已接线、真实外部已验证”三种不同强度的结论。
- 复跑针对性测试，并写出带提交范围和残余风险的技术判断。

## 课程方法

先全局、后细节；每课沿一条真实调用链穿透：

`设计问题 → 领域契约 → 生产调用链 → 核心源码 → 测试证据 → 技术判断`

每课约 20–25 分钟，只取得一个明确的理解成果。课程采用螺旋式穿透：先建立全局模型，再沿事实层、控制层和裁决层反复回到同一主链。源码引用必须紧邻业务和设计讲解；完整枚举、关系表和连通矩阵放在 `reference/`。

每课固定经过：上一课回忆、全局定位、生产调用链、最多两段核心源码、可复跑证据和脱稿审查输出。正文只保留结论与主链；替代方案、边界分支和完整错误列表放入折叠阅读或参考资料。

## 完成标准

浏览页面或点击按钮不代表掌握。只有你能不看答案复述调用链、解释关键守卫，并完成判断练习，才生成 learning record。

## 边界

- 课程位于 `teach-v2/`，不修改 `teach/` 1.x。
- 中文讲解，保留源码中的英文术语。
- 课程以学习时的 `HEAD + worktree` 为审查基线；页面行号只是入口，必须用符号名重新定位并记录实际 commit。
- CLI 和 Dashboard 只作为生产入口或投影出现，不作为课程主线。
