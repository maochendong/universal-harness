# NOTES

## 已确认的教学偏好

- `teach-v2/` 与 `teach/` 1.x 并行保留并纳入 Git。
- 面向技术设计者与核心源码审阅者，不按最终用户操作流程组织课程。
- 采用传统的自顶向下结构：先介绍全局，再解释局部；局部必须放回全局链定位。
- 采用“穿透式”教学：每课沿一条生产调用链从设计意图追到契约、实现、守卫和测试。
- 每课约 12–18 分钟，只解决一个设计问题，最多精读两个源码切片。
- 每段源码必须紧邻说明：为什么读、谁调用、输入输出、关键逻辑、失败语义、证据不能外推到哪里。
- 目标设计与当前实现双轨呈现；连通性标记必须同时说明证据维度。
- 第五课以后根据真实回答、误区和实验结果自适应生成。

## 统一课型

1. 在全局主链上定位本课。
2. 提出一个设计问题，说明学完能解决什么。
3. 先画生产调用链，再阅读源码。
4. 精读源码 1，并解释它在调用链中的职责。
5. 先预测下一层行为，再精读源码 2。
6. 运行一条针对性命令，限定证据范围。
7. 完成两道即时判断与一次脱稿回忆。
8. 推荐一个权威源码入口；需要继续追问时，向教学 Agent 提问。

## 状态口径

- **已连通**：当前生产消费者存在，且当前提交有仓库内测试或 Ledger 证据。
- **部分连通**：接口与生产路径存在，但当前外部 Provider、发布环境或完整闭环证据不足。
- **未连通**：只有目标设计或组件定义，没有生产消费点。

状态必须带 `source_commit` 与证据范围。历史真实调用只能证明历史，不自动证明当前提交。

首页的“已浏览”仅用于导航。只有用户通过复述、追踪或决策练习展示理解，才在 `learning-records/` 生成记录；现有 `teach/learning-records` 不迁移为学习成果。
