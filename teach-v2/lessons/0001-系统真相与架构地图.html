04 · 找对事实的住址

三层存储：同时看到，不等于同等可信

1

Git-native Ledger

唯一权威来源。append-only、可验证、可重放；批准、失效、Evidence 和 Snapshot 的完成事实在这里裁决。

2

SQLite Projection

可确定性重建的查询缓存。它让查询更快，但损坏时应从 Ledger 重建，不能倒过来修改权威历史。

3

Live Spool

可删除的实时观察。heartbeat、输出摘要与当前相位帮你看「此刻」，但不能升级为「已完成」。

Aha

Dashboard 可以在同一页合并三层读取，但这是展示上的汇合，不是权威上的平级。

真实源码 ↔ 中文翻译

存储层告诉你「什么是事实」；Edge 规则还要告诉你「事实如何传播」。下面 10 行从当前仓库原样复制。

TypeScript · propagation.ts:29–38 
export const PROPAGATION_RULES: readonly PropagationRule[] = [
  { type: "REFUTES", direction: "forward", defaultRisk: "high", allowsInference: false },
  { type: "VIOLATES", direction: "forward", defaultRisk: "high", allowsInference: false },
  { type: "BLOCKS", direction: "forward", defaultRisk: "high", allowsInference: false },
  { type: "VERIFIES", direction: "both", defaultRisk: "medium", allowsInference: true },
  { type: "ADDRESSES", direction: "inverse", defaultRisk: "medium", allowsInference: true },
  { type: "SHAPES", direction: "forward", defaultRisk: "medium", allowsInference: true },
  // SPECIFIES binds a contract to its subject in both directions; inferred
  // edges never propagate (designset lifecycle design 8.1).
  { type: "SPECIFIES", direction: "both", defaultRisk: "high", allowsInference: false },
读成中文
  1. 每种可传播关系都在表里明确登记，不由模型自由猜测。
  2. REFUTES、VIOLATES、BLOCKS 只向前传，且默认高风险、拒绝推理边。
  3. VERIFIES 可以双向检查；ADDRESSES 要逆向回溯；方向是代码中的政策，不是提示词的建议。
  4. SPECIFIES 双向、高风险，但禁止推理边传播：高风险计算不代表允许低置信关系越权。
05 · 把「看起来完成」改写成可复查结论

证据层级：结论必须带范围

1

文档自述

它可以描述目标，但可能过时。

2

Schema 与实现

证明对象和逻辑存在，不必然进入生产调用。

3

生产调用链 + 测试

证明组装与 fail-closed 边界在指定基线可复跑。

4

Ledger / Git / 外部证据

在明确 commit 和环境上证明真实结果；仍不可外推到未测范围。

06 · 最后一次不看答案的判断

决策练习：这能宣布「已完成」吗？

现场情境

一名 Agent 说「迭代完成」；Dashboard 中 Live Spool 显示 OperationCompleted；SQLite 也有一行 snapshot 投影。但 Git-native Ledger 没有 Snapshot transaction，对应 Gate Evidence 也找不到。

01

你的结论

只允许选：已连通、部分连通、未连通、或运行中但未完成。

02

你的证据

写出哪些是观察、哪些是投影、缺少哪项权威事实。

03

你的下一步

说明是继续等待、进入恢复，还是将投影视为漂移后重建。
