LESSON 0007 · CHANGE SEED → PATH → RISK → ADVISORY

模型可以补充候选，但不能改写确定性影响

Impact 的可信度来自可重放路径：从 ChangeSeed 沿受控关系和方向做确定性传播，再让模型只添加 inspect 候选。顺序颠倒，模型就会获得删除或降级既有影响的权力。

双图→确定性传播→风险评分→模型建议→ImpactSet
本课唯一胜利你能给一条变更解释影响路径、方向、风险与来源，并拒绝任何试图覆盖确定性 entry 的模型输出。

00 · RETRIEVAL FIRST

先恢复第 6 课的关系判断

  1. REALIZES 和 IMPLEMENTS 的 source 分别是什么？
  2. DEPENDS_ON 表示确定前置依赖，MAY_IMPACT 表示什么？
  3. 模型建议一条图中不存在的影响边，应直接当事实吗？

本课只需记住

  • 传播规则固定 relation、方向、默认风险与是否允许 inferred edge。
  • 确定性 entry 不可由模型删除、替换或改成更强行动。
  • 每条影响必须保留 path，风险结论才可解释。

01 · PRODUCTION CALL CHAIN

先算事实闭包，再接纳附加建议

ChangeSeed
changed nodes/files
Propagation
relation + direction
Scoring
path risk
Advisory
model additions
Merge + validate
additive only

已接受关系产生 deterministic entries；允许 inference 的 proposed edge 最多产生 inspect candidate。模型可以发现确定性图尚未表达的候选，但不能篡改已经由路径证明的节点、分类或风险。

关系强化：本课重点重访哪些边

DEPENDS_ON 双向发现任务耦合但不允许 inferred；MAY_IMPACT 正向扩展候选且允许 inferred；SUPPORTS 不属于传播规则，因为证据支持不等于变更依赖。REALIZES 从 Component 反向追到 CodeArtifact，IMPLEMENTS 从义务反向追到 Task。

02 · SOURCE READING 1

传播策略把同一条边的“能否走、往哪走、风险多高”固定下来

active graph edges → PROPAGATION_RULES → deterministic traversal

为什么读这段

图遍历不是通用 BFS；关系方向和业务风险必须进入规则表，否则反向路径会制造错误影响。

packages/graph/src/impact/propagation.ts · PROPAGATION_RULES 
{ type: "REFUTES", direction: "forward", defaultRisk: "high", allowsInference: false },
{ type: "VIOLATES", direction: "forward", defaultRisk: "high", allowsInference: false },
{ type: "BLOCKS", direction: "forward", defaultRisk: "high", allowsInference: false },
{ type: "VERIFIES", direction: "both", defaultRisk: "medium", allowsInference: true },
{ type: "ADDRESSES", direction: "inverse", defaultRisk: "medium", allowsInference: true },
{ type: "SHAPES", direction: "forward", defaultRisk: "medium", allowsInference: true },
// SPECIFIES binds a contract to its subject in both directions; inferred
// edges never propagate (designset lifecycle design 8.1).
{ type: "SPECIFIES", direction: "both", defaultRisk: "high", allowsInference: false },
{ type: "REALIZES", direction: "inverse", defaultRisk: "high", allowsInference: true },
{ type: "IMPLEMENTS", direction: "inverse", defaultRisk: "medium", allowsInference: true },
direction
forward 从 source 到 target，inverse 反向追踪，both 表示双向均有影响语义。
defaultRisk
同一路径上的边提供基础风险，再由 scoring 组合；它不是模型的自由文本评分。
allowsInference
只决定 proposed inferred edge 能否产生 inspect candidate，不会把 inferred 变成 accepted fact。
为什么关系不可合并
REALIZES 与 IMPLEMENTS 风险不同；合并会同时破坏端点和评分。

03 · SOURCE READING 2

模型 addition 命中 deterministic node 时直接拒绝

ImpactSet + advisory additions → mergeImpactAdvisory → additive merged set

为什么读这段

“additive only”必须落到冲突检测；否则模型用同一 node id 伪装 addition，实际覆盖确定性分类。

packages/graph/src/impact/impact-set.ts · advisory conflict guard 
const additions: ImpactEntry[] = [];
for (const addition of advisory.additions) {
  if (byNode.has(addition.node_id)) {
    throw new ImpactError(
      `advisory addition targets deterministic entry ${addition.node_id}; advisory output is additive only`,
    );
  }
上游
byNode 来自已经算出的 deterministic ImpactSet entries。
关键守卫
模型 addition 的 node id 已存在即报错；不是“保留模型版本”也不是静默忽略。
失败语义
整个 advisory merge 失败，原 ImpactSet 保持不变，便于审计模型越界。
还需后续校验
未冲突的 addition 仍要验证 node type、classification、risk 与 evidence 绑定。
先判断：模型认为 deterministic entry 风险太高，建议把 must-change 改为 inspect。正确动作是接受、取更低值，还是拒绝？说明权力边界。
