LESSON 0008 · CONTEXT → POLICY → APPROVAL → GRANT

治理层的核心不变量：权限只能收窄

ContextBundle 决定模型看见什么，Policy 决定系统允许什么，Approval 只放行精确版本。三者都不是给 Agent 增权的入口；任一绑定漂移，都必须重新裁决。

Impact / Plan→ContextBundle→EffectivePolicy→Approval→CapabilityGrant
本课唯一胜利你能审查多层 Policy 合并和 Approval digest 绑定，证明最终权限没有比任何上游约束更宽。

关系强化：治理链怎样落到边

对象 CONSTRAINED_BY Constraint 表达合法形状；对象 GOVERNED_BY Policy 表达生命周期权力；Finding 可 BLOCKS Task/Iteration；ApprovalRequest REQUESTS_APPROVAL_FOR 精确对象；Approval RESOLVES 请求，只有批准时才 APPROVES 对象。

02 · SOURCE READING 1

不同字段使用不同的“只收窄”代数

Policy layers → field entries → mergeField → EffectivePolicyField

为什么读这段

简单的 last-write-wins 会让下游层覆盖上游限制；hard_ceiling 与 allow_intersection 把不扩大权限写成计算规则。

packages/runtime/src/policy/evaluator.ts · mergeField 
case "hard_ceiling": {
  for (const entry of entries) {
    if (typeof entry.value !== "number" || !Number.isFinite(entry.value)) {
      throw new PolicyError(
        "policy_conflict",
        `policy field ${path}: hard_ceiling requires finite numeric values`,
      );
    }
  }
  const values = entries.map((entry) => entry.value as number);
  const merged = Math.min(...values);
  return {
    path,
    merge_operator: operator,
    value: merged,
    reason: `hard_ceiling:min(${values.join(",")})=${String(merged)}`,
    sources,
  };
}
输入校验
任何非有限数值都是 policy conflict，不做隐式转换。
收窄逻辑
多个预算上限取最小值；任何层都不能通过给更大数字扩大权限。
可解释性
结果保留 operator、计算 reason 与 sources，评审者能重算。
同类规则
allow 取交集；deny 与 approval requirement 取并集，因为更多拒绝/审批同样是收窄。

03 · SOURCE READING 2

批准的身份是四组绑定，而不是一枚永久布尔值

ApprovalRequest + current snapshot → bindingDrift → valid or replace request

为什么读这段

批准对象、仓库基线、Policy 或 Impact path 任一变化，评审者看到的输入已经不是当前执行输入。

packages/runtime/src/approval/invalidation.ts · bindingDrift 
export function bindingDrift(
  request: ApprovalRequestRecord,
  current: ApprovalBindingSnapshot,
): readonly string[] {
  const drifted: string[] = [];
  if (current.objectDigest !== request.object_digest) drifted.push("object_digest");
  if (current.baselineDigest !== request.baseline_digest) drifted.push("baseline_digest");
  if (current.policyDigest !== request.policy_digest) drifted.push("policy_digest");
  if (
    current.impactPath.length !== request.impact_path.length ||
    current.impactPath.some((entry, index) => entry !== request.impact_path[index])
  ) {
    drifted.push("impact_path");
  }
  return drifted;
}
四种漂移
对象内容、执行基线、治理规则和影响路径分别代表四个独立审查输入。
返回列表
函数不只给 true/false，而返回稳定字段名，供失效记录与替换请求解释原因。
生命周期后果
旧请求被 supersede，新的请求绑定当前 digests；不能修改旧 Approval 来“追上”新版本。
证据边界
digest 相等证明输入未漂移，不证明批准者身份、权限或决定本身有效；这些由其他守卫检查。
先判断：对象内容没变，但 Impact path 新增一个高风险节点。旧 Approval 能否继续使用？写出具体 drift 字段。
