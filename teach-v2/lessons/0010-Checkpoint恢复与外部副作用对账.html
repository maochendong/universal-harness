LESSON 0010 · CHECKPOINT → RESUME → RECONCILE

超时不是失败证明：恢复前必须先对账

本地步骤可以从合法 checkpoint 接续，外部副作用却可能在响应丢失前已经成功。盲目 retry 会重复付款、发布或删除；正确路径是先验证 checkpoint 绑定，再对每个未决 intent 探测结果。

Run records→Checkpoint→Resume validation→Intent reconcile→Successor Run
本课唯一胜利面对中断运行，你能区分 retry、resume 与 reconcile，并为 applied / not_applied / unknown 三种探测结果选择安全动作。

01 · THREE DIFFERENT ACTIONS

retry、resume、reconcile 解决的是不同不确定性

Retry

用相同 idempotency key 再次提交已知可重试动作。前提是系统或 provider 能证明第一次未应用，或完成结果已缓存。

Resume

从 committed checkpoint 的合法前缀继续 workflow，建立新 attempt/successor Run，不复制已完成节点与 Evidence。

Reconcile

对未决外部 intent 查询 provider：已应用则复用，未应用才允许 retry，未知则人工裁决。

Graph reconcile

把运行工件和 accepted Ledger 重新物化成缺失 Evidence/edges；不是重演外部副作用。

02 · SOURCE READING 1

Resume 在创建任何新记录前重新验证三类绑定

workflow operation → latest checkpoint → binding revalidation → interrupted runs

为什么读这段

Checkpoint 是过去时的合法状态；恢复时当前 baseline 或治理输入可能已变化，不能直接信任旧授权。

packages/runtime/src/workflow/resume.ts · resume validation 
const committed = latestValidCheckpoint(harnessRoot, operations, workflowOperationId);
if (committed === undefined) {
  throw new WorkflowError(
    "checkpoint_not_found",
    `workflow operation ${workflowOperationId} has no valid checkpoint to resume from`,
  );
}
const { workingState } = committed;

// Re-verify bindings recorded in the checkpoint before any new commit.
const baseline = deps.readBaseline();
if (baseline !== workingState.baseline_commit) {
  throw new WorkflowError(
    "baseline_mismatch",
    `baseline drifted since the checkpoint: expected ${workingState.baseline_commit}, current ${baseline}`,
  );
}
const allowedDigests = artifactDigestAllowlist(operations, workflowOperationId);
verifyApprovalBindings(harnessRoot, allowedDigests, workingState);
verifyContextBundleBinding(harnessRoot, allowedDigests, workingState);
只读 committed checkpoint
latestValidCheckpoint 以 Ledger operations 验证 checkpoint，不采用任意磁盘快照。
baseline guard
工作树基线变化意味着旧执行前提失效，直接报 baseline_mismatch。
digest allowlist
Approval 和 Context 必须来自该 operation 已提交的 artifact digests，防止路径注入未授权文件。
时序
这些检查发生在新 attempt、successor Run 和新 Ledger commit 之前。

03 · SOURCE READING 2

Provider 不能证明结果时，唯一自动决策是 manual_required

unresolved ActionIntent + ToolRegistry + probe → reconcileIntent → decision

为什么读这段

这段 switch 是外部副作用的安全真值表：只有 provider 的肯定证明才能复用或重试。

packages/runtime/src/tools/reconciliation.ts · probe outcome 
const outcome = await probe(intent);
switch (outcome) {
  case "applied":
    return decide(
      intent,
      "reuse_result",
      `provider proves the effect of intent ${intent.intent_id} applied; the side effect ` +
        "is reused, not replayed",
    );
  case "not_applied":
    return decide(
      intent,
      "retry_allowed",
      `provider proves the effect of intent ${intent.intent_id} was not applied; ` +
        "retrying the idempotency key is safe",
    );
  case "unknown":
    return decide(
      intent,
      "manual_required",
      `provider cannot prove the outcome of intent ${intent.intent_id}; human review is required`,
    );
}
applied
复用已发生的结果，不重放副作用；后续需要补齐本地 result/evidence 记录。
not_applied
provider 明确证明未发生，才允许使用原 idempotency key 重试。
unknown
不确定性不会被当作失败；自动流程停止并请求人工核查。
额外 fail closed
Tool 不再注册、声明 manual reconciliation、或没有 probe，都返回 manual_required。
