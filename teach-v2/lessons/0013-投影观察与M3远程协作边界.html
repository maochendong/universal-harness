LESSON 0013 · AUTHORITY → PROJECTION → REMOTE CONTROL

看得见、查得到、远程可协作，是三种不同能力

Live Spool 允许丢失，SQLite/Dashboard 必须可重建，Git/Ledger 才是权威。M3 又增加 Control Ref、Lease、远程 Approval 和目标分支 CAS；定义与部分 connect/disconnect slice 存在，不等于完整远程闭环已连通。

Git / Ledger→SQLite projection→Dashboard→M3 Coordinator→Remote CAS
本课唯一胜利你能为任意协作数据指出权威源，并把 M3 结论严格拆成“目标设计、已提交基础、当前实现切片、真实外部验证”四层。

00 · RETRIEVAL FIRST

先恢复权威方向

  1. Ledger 与 SQLite 不一致时，修复方向是什么？
  2. Projection 更新失败后，能否盲目重试已经成功的权威 append？
  3. Operation Branch 上有 merge commit，是否等于 Target Branch 已接受？

本课只需记住

  • Live observation 可丢；SQLite/Dashboard 可重建；Git/Ledger/Control Ref 才承载权威事实。
  • M3 的 Coordinator 管远程写入资格，不裁决 Requirement、Gate 或 Evidence 内容。
  • 只有重新验证并 CAS 更新 Target，Integration 才被接受。

01 · TARGET VS CURRENT

M3 必须按四层证据报告，不能只说“正在实现”

层 当前能确认 不能外推
目标设计 单 Coordinator、Control Ref、Lease/fencing、远程 Approval、Operation Branch、Target CAS 的正式设计已批准。 设计通过不等于生产代码或远程环境可用。
已提交基础 Protocol 1.2 五类 record、reader gate、Coordinator Port 与 connect/disconnect slice 已进入当前 Git 历史。 Port 和局部 slice 不证明 lease、approval、integration 全闭环。
当前实现切片 Coordinator 源码明确把 Lease、Approval、Integration command 留给后续任务，并为它们返回类型化 unavailable failure。 command 已进入 union type 不代表对应生产分支已经实现。
外部证据 本课没有 GitHub/GitLab/Gitee OAuth、Control Ref 保护、Lease、remote approval 与 target CAS 的同一提交端到端证据。 因此 M3 当前只能标记部分实现/未完成外部连通。
M3 的权威分配

项目 Requirement/Design/Plan/Evidence/Snapshot 仍在项目 Git/Ledger；Principal/Lease/Remote Approval 在 protected Control Ref；Operation 工作在候选 branch；只有 Target CAS 成功后 Integration 才被接受；Coordinator SQLite 只存可重建投影。

02 · SOURCE READING 1

ObservationPublisher 在类型旁明确放弃权威性

Run lifecycle → ObservationPublisher → Live Spool / SSE

为什么读这段

实时状态要低延迟、限流和可删除；若把它当恢复或审计依据，就会让丢包改变系统事实。

packages/runtime/src/observability/publisher.ts · authority comment 
/**
 * Lossy live-observation publisher. It never writes authoritative state and
 * may be deleted or fail independently of resume, audit and snapshot state.
 */
export class ObservationPublisher implements ObservationPublisherPort {
谁生产
Run、Gate、Approval 等运行过程发布观察事件，供 Live Spool 与 Dashboard 实时消费。
lossy 的含义
允许节流、截断、segment 淘汰或整个缓存删除；这些都不能影响 workflow correctness。
不能承载
Resume、Audit 和 Snapshot 必须读取 Ledger/artifacts，不得从最后一条 SSE 消息推断权威状态。
设计收益
观察面失败可独立降级，不会阻塞或伪造事实提交。

03 · SOURCE READING 2

Coordinator Port 很深，但当前 outcome 只覆盖连接切片

CLI / Dashboard / Kernel → CollaborationCoordinatorPort → platform/Git/projection adapters

为什么读这段

外部调用者只看 command/query；OAuth、平台权限、Git CAS 与 SQLite 重建留在模块内部。但接口全集不代表每个 command 已实现。

packages/runtime/src/collaboration/port.ts · public coordinator port 
export type CollaborationOutcome =
  ConnectedOutcome | DisconnectedOutcome | CollaborationFailedOutcome;

export interface CollaborationCoordinatorPort {
  execute(
    command: CollaborationCommand,
    session: CollaborationSession,
  ): Promise<CollaborationOutcome>;
  query(query: CollaborationQuery, session: CollaborationSession): Promise<CollaborationView>;
}
深模块边界
CLI/Dashboard 只提交判别式 command/query，不理解平台角色、fencing 或 CAS 实现细节。
当前事实
Coordinator comment 明确 connect/disconnect 为当前 slice；Lease、Approval、Integration commands 由后续任务实现。
typed failure
未实现命令返回 coordinator_unavailable，而不是伪成功或自由文本状态。
当前提交范围
connect/disconnect 和 projection failure 语义已经提交；其余 command 仍由源码明确标记为后续 slice。
结论练习：Protocol records 测试与 connect tests 全绿后，可以说“远程协作已连通”吗？请列出仍缺的 Lease、Approval、Integration 与真实平台证据。

05 · EVIDENCE AND MASTERY

分开验证稳定投影与 M3 已提交基础

Observation + Dashboard + committed collaboration slices

pnpm exec vitest run packages/runtime/test/observability/publisher.test.ts packages/dashboard/test/sse.test.ts packages/core/test/collaboration/records.test.ts packages/core/test/protocol/protocol-1.2.test.ts packages/runtime/test/collaboration/connection.test.ts packages/runtime/test/collaboration/coordinator.test.ts

证据边界：若工作树含未提交 coordinator 修改，本次结果证明的是该工作树，不是 HEAD。即使全绿，也不包含真实 OAuth、protected Control Ref、远程 Lease 与 Target CAS。

边界判断

1. Dashboard SSE 显示 RunCompleted，能否单独作为完成事实？

2. M3 中 Integration 最终接受点是？

3. command union 包含 accept_integration，是否证明已实现？

M3 范围化结论

  1. 画出 Replica → Coordinator → Git Remote/平台的目标架构。
  2. 为项目 Ledger、Control Ref、Operation Branch、Target Branch、SQLite 分别标权威性。
  3. 写四段结论：设计、已提交基础、当前实现切片、真实外部验证；禁止使用笼统“已完成”。
