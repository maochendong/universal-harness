LESSON 0011 · EVIDENCE → VERDICT → SNAPSHOT

绿色测试只是输入，不是“任务完成”本身

完成判断要把 Assertion、required Gate、Evaluation、TDD 序列、Finding、外部 Action 和 Evidence 新鲜度合在一起。TaskVerdict 裁决单个任务，Snapshot 再裁决整次迭代。

Run results→Evidence / Gate→TaskVerdict→Completion blockers→Snapshot
本课唯一胜利你能指出一次“tests green”结论还缺哪些绑定，并根据 blockers 判断 Snapshot 应是 completed、blocked 还是拒绝构建。

00 · RETRIEVAL FIRST

先恢复“记录不等于裁决”

  1. Run PRODUCES Evidence，是否自动说明 Requirement 通过？
  2. Test VERIFIES Requirement 与 Evidence SUPPORTS Requirement 有何不同？
  3. 一次未决外部 Action 会怎样影响 completed Snapshot？

本课只需记住

  • Assertion 通过要求测试身份、required gates、evidence requirements 与 active Evaluation 同时满足。
  • Strict TDD 还要求合法 Red/Green/Refactor 证据序列。
  • Snapshot completed 要求所有 required tasks、blocking findings、mandatory evidence 与 external actions 全部闭合。

01 · TWO-LEVEL VERDICT

先判任务，再判迭代

Assertion
tests + requirements
Gate / Eval
machine-checkable proof
TaskVerdict
task acceptance
Blocker scan
global closure
Snapshot
iteration state

VERIFIES 表达 Test 对 Requirement/Constraint 的检查关系，EVALUATES 表达 EvaluationCase 对 Task/Run 的裁判，SUPPORTS/REFUTES 表达 Evidence 的方向。它们分开，TaskVerdict 才能判断“有测试”“测试执行”“证据当前有效”“质量评估通过”四件不同的事。

Kernel-only Profile 为什么不因缺 Evaluation 而失败

未激活 Evaluation module 时，该维度是 absent，不是 vacuously failed；但 planner 若仍生成 evaluation_evidence 要求，TaskVerdict 会 fail closed。这保持 CapabilityPlan 与验收义务一致。

02 · SOURCE READING 1

每个 Assertion 都独立聚合 Gate、Evaluation 与 Evidence 要求

Assertions + Gates + Evaluations + TDD → buildVerdict → TaskVerdict

为什么读这段

全局“任意测试绿”不能代替逐 Assertion coverage；这里按 assertion id 确认所有 required gate 和 evidence requirement。

packages/runtime/src/evaluation/task-verdict.ts · assertion verdicts 
const requiredGates = assertion.required_gate_ids.map((gateId) => gateById.get(gateId));
const gatesPass =
  requiredGates.length === assertion.required_gate_ids.length &&
  requiredGates.every((gate) => gate?.passed === true);
const evidenceIds = uniqueSorted([
  ...requiredGates.flatMap((gate) => (gate === undefined ? [] : [gate.evidence_id])),
  ...input.evaluations.map((evaluation) => evaluation.evidence_id),
]);
const requirementsSatisfied = assertion.evidence_requirements.every((requirement) => {
  if (requirement === "gate_evidence") return requiredGates.length > 0;
  if (requirement === "evaluation_evidence") {
    return evaluationActive && input.evaluations.length > 0;
  }
  return evidenceIds.length > 0;
});
Gate identity
按 required_gate_ids 精确查找；缺一个 gate 和 gate failed 都使 gatesPass=false。
Evidence aggregation
只收集实际 Gate/Evaluation 绑定的 evidence id，并去重排序形成稳定记录。
Profile awareness
evaluation_evidence 只有 Evaluation active 且确有结果时成立。
最终还不够
后续还检查 Assertion 有 test id、所有 assertions 通过以及 strict TDD verdict 合法。

03 · SOURCE READING 2

Snapshot 把任务外的全局未完成项重新列成 blockers

TaskVerdicts + Findings + Evidence + Actions → snapshotCompletionBlockers → status

为什么读这段

即使所有 TaskVerdict passed，开放的 blocking Finding、陈旧 Evidence 或未决外部 Action 仍可阻止迭代完成。

packages/runtime/src/snapshot/builder.ts · completion blockers 
for (const finding of [...(input.findings ?? [])].sort((left, right) =>
  left.finding_id < right.finding_id ? -1 : 1,
)) {
  if (!finding.blocking) continue;
  if (finding.status !== "closed" && finding.status !== "superseded") {
    blockers.push(`blocking finding ${finding.finding_id} is ${finding.status}`);
  }
}
for (const evidence of [...(input.evidence ?? [])].sort((left, right) =>
  left.evidence_id < right.evidence_id ? -1 : 1,
)) {
  if (!evidence.mandatory) continue;
  if (evidence.stale) {
    blockers.push(`mandatory evidence ${evidence.evidence_id} is stale`);
  } else if (evidence.provisional || !evidence.passed) {
    blockers.push(`mandatory evidence ${evidence.evidence_id} has no current passing verdict`);
  }
}
稳定顺序
Finding 和 Evidence 先排序，保证相同输入产生相同 blocker 列表和 digest。
Finding 生命周期
blocking Finding 只有 closed 或 superseded 才不再阻塞；“有人在处理”仍不是完成。
Evidence 生命周期
mandatory evidence 不能 stale、provisional 或 failed；历史绿灯不会自动延续到新基线。
下游
有 blockers 时请求 completed 会抛错；可恢复中断必须构建带 resume_phase 的 blocked Snapshot。
先判断：required tasks 全部 passed，但 mandatory Evidence 绑定的是旧 code digest。Snapshot 能否 completed？应记录哪个 blocker？

完成裁决

1. 任意一组测试绿，Task 是否必然 passed？

2. mandatory Evidence stale，Snapshot 状态应怎样？

3. EvaluationCase 对 Run 的关系是？

完成性审查输出

  1. 为一个 Assertion 列出 test ids、required gate ids、evidence requirements 与 evaluation 状态。
  2. 从 TaskVerdict 继续列出 Snapshot 的 tasks、findings、evidence、external actions blockers。
  3. 写一句“测试全绿但不能放行”的范围化结论。
